# 记忆召回

## Purpose

让写进库里的内容都能被找回来：交接包、主题汇编和 agent 自己记下的结论进入同一套检索，每条都能追到来源会话与具体条目，新结论可以取代旧结论，写错的可以作废而保留历史。

## ADDED Requirements

### Requirement: 非会话文档进入检索

系统 SHALL 把交接包与主题汇编产物登记进检索索引，使其与会话条目一样能被关键词命中。登记 MUST 在文档生成时完成，MUST NOT 依赖使用者手动触发全量重建。

#### Scenario: 检索到交接包里的待办

- **WHEN** 交接包正文里写着「稠州五期逾期」，而库里没有任何会话提到这几个字
- **THEN** 检索这个词时结果里出现这份交接包，并标明它是交接包而不是会话

#### Scenario: 检索到汇编结论

- **WHEN** 使用者检索一个只在汇编产物里出现过的结论词
- **THEN** 结果里出现对应汇编文档，并给出它覆盖的时间范围

#### Scenario: 文档已从磁盘删除

- **WHEN** 使用者在磁盘上删掉某份交接包后执行一次补录
- **THEN** 该文档从索引里移除，检索不再返回它

### Requirement: 每条记忆文档带来源与时间

系统 SHALL 为每份记忆文档记录标题、类别、文件位置、生成时间与关联会话。

#### Scenario: 交接包关联会话

- **WHEN** 交接包由某个会话产出
- **THEN** 取回该文档时给出这个会话的标识，使用者能回到原会话

#### Scenario: 汇编没有单一来源会话

- **WHEN** 汇编产物由多个会话汇总而成
- **THEN** 该文档标注为没有单一来源会话，并给出覆盖的会话数与时间范围，MUST NOT 伪造一个来源会话

### Requirement: 结论条目可写入

系统 SHALL 允许 agent 在做事过程中主动写入一条结论，每条结论 MUST 包含正文与类别，类别取值为决策、偏好、事实。

#### Scenario: 记下一条决策

- **WHEN** agent 判断「发布走 OpenSpec 归档流程」值得记住并写入
- **THEN** 返回新条目的标识，之后按关键词能检索到它

#### Scenario: 缺少出处

- **WHEN** 写入时没有给出任何来源会话
- **THEN** 系统仍然保存，但把它标为无出处，检索与取回结果里一并标出，MUST NOT 假装它有来源

#### Scenario: 正文为空或超长

- **WHEN** 正文去掉空白后为空，或超过允许长度
- **THEN** 拒绝写入并说明原因与允许长度，MUST NOT 静默截断后照收

#### Scenario: 类别写错

- **WHEN** 类别不在决策、偏好、事实三者之内
- **THEN** 返回错误并列出允许的取值，不写入任何内容

### Requirement: 结论可取代与作废

系统 SHALL 允许新结论取代旧结论，也允许把写错的结论作废。被取代或被作废的结论 MUST 保留并标注状态与时间，MUST NOT 物理删除。

#### Scenario: 新结论取代旧结论

- **WHEN** agent 写入一条与已有结论冲突的新决策并声明取代它
- **THEN** 旧结论标为已取代并记下被哪一条取代，默认检索不再返回它

#### Scenario: 作废写错的结论

- **WHEN** 使用者发现一条结论记错了并作废它
- **THEN** 该条目标为已作废，正文与出处保留，默认检索不再返回它

#### Scenario: 取代不存在的条目

- **WHEN** 取代时给出的目标标识在库里不存在
- **THEN** 返回错误并说明没有写入任何内容

### Requirement: 结论出处可追溯

系统 SHALL 为每条结论记录来源会话与具体条目。引用到的会话或条目已不存在时必须说明，MUST NOT 返回看似有效的出处。

#### Scenario: 从结论回到原话

- **WHEN** 使用者打开一条结论的出处
- **THEN** 定位到来源会话中被引用的那一条，与检索命中跳转使用同一种定位方式

#### Scenario: 来源会话已被删除

- **WHEN** 结论引用的会话在库里已不存在
- **THEN** 结论照常显示，出处标注为来源已不在，并且不提供跳转

### Requirement: 检索范围可切换

系统 SHALL 让检索按会话条目、记忆文档或两者同时进行，默认范围 MUST 保持只看会话条目，使既有调用方的结果不变。

#### Scenario: 只在记忆里找

- **WHEN** 使用者把范围设为仅记忆并检索
- **THEN** 只返回交接包、汇编与结论三类命中

#### Scenario: 同时找

- **WHEN** 范围设为全部
- **THEN** 两类命中同列出现，各自标明类别

#### Scenario: 会话命中把名额占满

- **WHEN** 范围设为全部且某个词在会话里凑够条数上限，同时也有记忆文档命中
- **THEN** 记忆命中也出现在结果里，MUST NOT 因为会话先占满名额就一条都不给

### Requirement: 按会话取回记忆

系统 SHALL 允许按会话标识取回该会话产出的有效结论与交接包。

#### Scenario: 接手前先看结论

- **WHEN** agent 拿到一个会话标识并请求它的记忆
- **THEN** 返回该会话的结论与交接包，已作废与已取代的单列或不出现在默认结果里

#### Scenario: 该会话没有记忆

- **WHEN** 该会话既没有结论也没写过交接包
- **THEN** 明确回答没有，MUST NOT 用其他会话的内容顶替

### Requirement: 重复写入不产生重复条目

同一会话里同一正文的结论重复写入 MUST NOT 产生第二条。

#### Scenario: 同一件事写两次

- **WHEN** agent 在同一个会话里把同一条决策写了两遍
- **THEN** 库里只有一条，第二次写入返回已有条目的标识并说明是重复

### Requirement: 索引可修可补

系统 SHALL 在索引与磁盘不一致时提供补录手段，并报告补录与跳过的份数。

#### Scenario: 早期产物未入索引

- **WHEN** 使用者对已存在的交接包与汇编执行一次补录
- **THEN** 报告新增与跳过的份数，之前搜不到的历史产物随后能被检索到

#### Scenario: 补录可重复执行

- **WHEN** 使用者在没有新产物的情况下再执行一次补录
- **THEN** 第二次报告全部跳过，且索引里的文档总数不变
