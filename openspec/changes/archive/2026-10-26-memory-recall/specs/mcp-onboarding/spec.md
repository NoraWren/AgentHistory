# 接入引导

## MODIFIED Requirements

### Requirement: 失效路径可一键修复

当已接入客户端的登记指向的可执行文件已不存在，或指向的已不是当前这份程序时，系统 SHALL 能把这些登记整体改写为当前可执行文件路径，并报告修改了哪些文件。判定 MUST 以「是否指向当前程序」为准，文件存在与否只用于区分说明；并 SHALL 支持只列出待修清单而不写入。

#### Scenario: 应用被移动后修复

- **WHEN** 应用被移动到新位置，已有登记仍指向旧路径
- **THEN** 修复动作把所有失效登记改写为当前路径，并在完成后重新握手确认

#### Scenario: 无需修复

- **WHEN** 所有已接入客户端的路径都有效
- **THEN** 修复动作不出现在可执行状态，或明确报告无需修复

#### Scenario: 升级后仍指向旧版本

- **WHEN** 客户端登记的可执行文件存在但已不是当前这份程序，握手只能拿到旧版本的工具集
- **THEN** 该登记计入待修并改写为当前可执行文件路径；判定 MUST 先比较路径是否指向当前程序，文件存在与否可以区分说明，并支持只列出待修清单而不写入

#### Scenario: 同一客户端两种问题并存

- **WHEN** 某个客户端既有失效登记又需要改到当前程序
- **THEN** 该客户端只计一次，不重复改写同一份配置
