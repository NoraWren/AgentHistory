# 规格变更：MCP 接入面板

## Purpose

让使用者在应用内看清每个 Agent 客户端到底有没有接上本服务、接上的能不能真用，并能在这里完成接入、移除和失效修复，不必再去逐个手改配置文件。

## ADDED Requirements

### Requirement: 逐客户端呈现接入状态

系统 SHALL 为本机每个受支持的 Agent 客户端给出接入状态，状态取值至少区分：已接入、已配置但连接不通过、未配置、客户端未安装。每行 MUST 能看出配置写在哪里、最近一次检查在什么时候，以及检查不出来时的原因。

#### Scenario: 列出当前接入情况

- **WHEN** 使用者打开接入面板
- **THEN** 每个客户端占一行，显示状态、配置路径与最近检查时间，未接入的客户端也列出而不是隐藏

#### Scenario: 客户端未安装

- **WHEN** 某个客户端的根目录不存在
- **THEN** 该行显示为客户端未安装，说明检查过的路径，并且不提供接入动作

#### Scenario: 配置存在但连不上

- **WHEN** 配置文件里有本服务的登记但握手没有通过
- **THEN** 状态显示为已配置但连接不通过，并写出失败原因，不能显示成已接入

### Requirement: 以真实握手验证接入是否可用

接入状态的判定 MUST 以实际建立会话为准，不能只看配置文件里有没有这一条。系统 SHALL 拉起一次本服务的 MCP 进程，完成初始化握手并取回工具清单，据此判断是否可用以及可见工具数量。

#### Scenario: 握手成功

- **WHEN** 进程能完成初始化并返回工具清单
- **THEN** 该客户端判定为已接入，并显示可见工具数

#### Scenario: 可执行文件不存在

- **WHEN** 配置里登记的可执行文件路径在本机已不存在
- **THEN** 判定为连接不通过，原因为路径失效，并标记为可一键修复

#### Scenario: 握手超时

- **WHEN** 进程启动后在限定时间内没有完成握手
- **THEN** 判定为连接不通过，原因为超时，界面 MUST NOT 卡住等待

### Requirement: 接入与移除只改动本服务这一条登记

系统 MUST 在写入前给出将要改动的文件与内容差异，写入前备份原文件，并且只增删本服务的登记项，同一文件里的其他服务配置 MUST 原样保留。

#### Scenario: 接入一个未接入的客户端

- **WHEN** 使用者对某个未接入客户端执行接入
- **THEN** 先展示目标文件与差异，确认后写入，其他登记项保持不变

#### Scenario: 移除已有登记

- **WHEN** 使用者移除某个客户端的接入
- **THEN** 只删除本服务这一条，该文件中其他服务的配置与格式保持原样

#### Scenario: 取消写入

- **WHEN** 使用者在预览阶段取消
- **THEN** 目标文件不被修改，也不产生备份

### Requirement: 优先使用客户端自带的登记命令

当客户端提供官方命令用于登记 MCP 服务时，系统 MUST 优先调用该命令完成接入与移除，MUST NOT 直接编辑其配置文件。

#### Scenario: 客户端有官方命令

- **WHEN** 目标客户端提供登记 MCP 服务的命令
- **THEN** 系统调用该命令完成接入，并在结果中写明用的是命令而不是编辑文件

#### Scenario: 命令执行失败

- **WHEN** 官方命令返回非零退出码
- **THEN** 报告失败原因与命令输出，MUST NOT 改而静默编辑配置文件

### Requirement: 区分插件式接入与配置式接入

对需要通过安装插件才能接入的客户端，系统 MUST 把它标注为插件式接入，并分别说明插件是否已安装，MUST NOT 与配置式接入混为一种状态。

#### Scenario: 插件已安装

- **WHEN** 某个客户端要求插件接入且插件已安装在本机
- **THEN** 显示为插件已装，并给出安装位置

#### Scenario: 插件未安装

- **WHEN** 某个客户端要求插件接入但插件未安装
- **THEN** 显示为插件未装，并给出可执行的安装指引，不显示「接入」按钮

### Requirement: 失效路径可一键修复

当已接入客户端的登记指向的可执行文件已不存在时，系统 SHALL 能把这些登记整体改写为当前可执行文件路径，并报告修改了哪些文件。

#### Scenario: 应用被移动后修复

- **WHEN** 应用被移动到新位置，已有登记仍指向旧路径
- **THEN** 修复动作把所有失效登记改写为当前路径，并在完成后重新握手确认

#### Scenario: 无需修复

- **WHEN** 所有已接入客户端的路径都有效
- **THEN** 修复动作不出现在可执行状态，或明确报告无需修复

### Requirement: 提供可复制的配置片段

系统 SHALL 能为任一客户端生成符合其格式的配置片段，供使用者手工粘贴，片段内容 MUST 与本机实际可执行文件路径一致。

#### Scenario: 复制配置片段

- **WHEN** 使用者对某个客户端选择复制配置
- **THEN** 剪贴板中是可直接粘贴的片段，其中的路径与当前可执行文件一致

### Requirement: 接入状态可见但不打扰

系统 MUST 在应用内常驻展示接入检查结论，但 MUST NOT 在启动或同步时以弹窗打断使用者；只有当检查发现连接不通过时才提示，并在修复后自动清除该提示。

#### Scenario: 启动时存在未接入客户端

- **WHEN** 应用启动且存在未接入的客户端
- **THEN** 不弹出提示，仅在接入面板与菜单栏中标注

#### Scenario: 已接入的客户端握手失败

- **WHEN** 原本可用的客户端握手失败
- **THEN** 给出一次提示，说明哪个客户端失败及原因，修复成功后提示消失

### Requirement: 接入状态可脚本化读取

系统 SHALL 提供命令行方式输出各客户端的接入状态与握手结果，输出需便于机器解析，并对检查失败给出非零退出码。

#### Scenario: 脚本查询状态

- **WHEN** 使用者以命令行方式查询接入状态
- **THEN** 输出每个客户端的状态与原因，全部可用时退出码为零

#### Scenario: 存在失败的客户端

- **WHEN** 查询时至少一个客户端已配置但握手失败
- **THEN** 退出码为非零，输出中写明是哪个客户端、什么原因
