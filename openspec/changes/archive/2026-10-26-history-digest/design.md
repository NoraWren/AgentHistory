# 设计

## 背景

动机见 proposal.md。这里记录决定实现形状的实测数据，均取自本机统一库（清理假会话后 2,329 个会话、21.6 万条记录）。

| 现象 | 实测值 | 对设计的影响 |
| --- | --- | --- |
| 七天轮次量 | 335 轮、57 个会话 | 材料量在十万字级，必须分段 |
| 首次取数耗时 | 3 分钟（无索引）→ 1.6 秒（加索引） | 索引是功能的前提，不是优化 |
| 自动化模板轮 | 七天里 77 轮 | 必须过滤，否则材料被心跳冲淡 |
| `claude -p` 空跑 | 124 秒 | 超时下限要放到分钟级 |
| 单段材料上限 | 24,000 字 | 一天基本一次调用，超了天内再拆 |
| 假会话 | 38 条（会进汇编素材） | 默认命令必须带 `--no-session-persistence` |

## 目标与非目标

**目标**

- 一次点击拿到这一周做了什么、结论是什么、还有什么没定。
- 材料按天完整覆盖，不因为长度丢内容。
- 模型不可用时仍有可读产出。

**非目标**

- 不搬原文，产物是结论，不是转写。
- 不做定时自动汇编，仍是用户点一次跑一次。
- 不把汇编产物写回库内，产物是独立 Markdown 文件。
- 不追求一次调用搞定，接受十来次调用的总耗时。

## 决策

### 先按天分段，再合并

最早的实现把全部材料拼成一份、超长就截断到 48,000 字。七天 1,000 多轮被砍到 59 轮，最早的内容全丢。改成按天分段后，每天各自一次调用，跨天的合并再用一次：

```
取数（按天分组）
   ├── 10-19 一天的材料 ──> 调用 1 ──> 当天要点
   ├── 10-20 一天的材料 ──> 调用 2 ──> 当天要点
   │     …（天内超 24,000 字再拆段，段内独立调用）
   └── 10-26 一天的材料 ──> 调用 N ──> 当天要点
                └── 合并调用 ──> 最终汇编
```

调用次数等于有内容的天数加一。实测 13 天窗口 15 次调用，各段并发 5 路。

### 分段不丢不重

天内拆段按轮次边界切，不按字符硬切，同一轮不会跨两段。测试里对同一批轮次断言「段内轮次之和等于总轮次，且每轮只出现在一段」。

### 降级路径逐级退

```
模型正常        → 分段提炼 + 合并
某天失败        → 该天退规则摘要，其余天照常提炼
各天全失败      → 整份退按天摘要
合并失败        → 各天要点按天拼接
```

每条降级都在结果里写一句原因，不让用户猜「为什么这次像没提炼过」。

### 模型原样回显算失败

模型偶尔把输入材料连同 `# 对话材料` 这个标题一起吐回来。这不是结论，判为失败并走降级，避免产物变成一份换了排版的原文。

### 命令可配置，默认不落会话

提示词走标准输入，正文从标准输出读回，任何命令行工具都能接。默认是 `claude -p --no-session-persistence`：`claude -p` 本机能无头调用、不用配 key；`--no-session-persistence` 是必须项，实测不加时每次调用都会在 `~/.claude/projects/<cwd>` 落一份 jsonl，同步时被当成真实会话收进库，甚至反哺进下一次汇编素材。

已经存过旧默认值的用户，启动时会被迁移到新默认值。

### 临时目录按路径片段认

清理假会话不能只看当前库根目录：换过库目录、或用副本库跑过时，历史里留下的是别的根下的路径。所以按 `/digests/work/` 这个片段判断，覆盖所有根。项目路径落在临时目录下的会话，同步时也直接跳过。

## 风险与限制

- 总耗时由模型排队决定，本机 `claude -p` 空跑就 124 秒，七天汇编实测 463 秒。界面上明确写「模型提炼通常要几十秒」，不给虚假进度。
- 模板轮过滤靠关键词（`<heartbeat>`、`<automation_id>`、`Automation ID:`），换了模板格式可能漏判；漏判的后果是材料里多几句空转，不影响正确性。
- 汇编产物不是事实核查，模型仍可能把细节写错；需要精确数字和单号的场景，应回到原文核对。
