# 提案：按时间范围的主题汇编

## 为什么

统一库解决了「找得到」，没有解决「看得完」。本机库里有 2,332 个会话、21.6 万条记录，一周下来光 Codex 就有上千轮对话。写周报、写复盘、给上级汇报时，真正的动作是「这一周到底做了什么」，而现在只能靠检索关键词一条条翻回去看，翻完还要自己在脑子里合并同类项。

这件事不适合让应用只做排序和过滤：同一件事在多个会话里被反复讨论，跨天、跨项目、跨客户端。要得到结论，必须把材料读一遍再压成短文本，这是模型擅长、检索不擅长的事。本机的 `claude -p` 已经能无头调用，不需要额外配 API key，接上就能用。

## 变更内容

- 新增主题汇编：选时间范围、来源、项目，把这段时间的对话压成一份带日期分节的 Markdown。
- 汇编按天分段，每天一次提炼，再合并成全文；材料超长时在天内继续拆段，不丢最早的轮次。
- 略过自动化心跳与模板轮次，避免定时任务的空转把材料冲淡。
- 模型失败逐级降级到按天摘要，并写明原因。
- 模型命令在界面和命令行都能改，默认为不落会话记录的 `claude -p --no-session-persistence`。
- 新增 `AgentHistory digest` 与 `AgentHistory digest-clean` 两个子命令。
- 新增工具栏「汇编」按钮与 ⌘D 菜单项。

## 能力

### 新增能力

- `history-digest`：把一段时间范围的对话汇编成结论文档，支持模型提炼与按天摘要两种模式。

### 修改能力

无。同步仍由用户手动触发，本次不给同步加定时。

## 影响

- 统一库新增 `turns(thread_id)`、`items(turn_id)` 索引；没有这两个索引时七天汇编取数要三分钟，加上后 1.6 秒。
- 产物默认写到 `~/.agent-history/digests/`，临时材料在 `~/.agent-history/digests/work/`。
- 汇编会调用外部模型命令，一次七天汇编通常十来次调用，总耗时以模型排队为准，本机实测约八分钟。
- 不落会话记录的命令参数是必须项：不加时每次调用都会在 `~/.claude/projects` 留一份会话，下次同步会被当成真实对话收进库。
