# 历史索引

## Purpose

把本机多个 Agent 客户端产生的会话归一化到一份可检索、可增量的本地索引里，作为浏览和同步的共同数据源。

## ADDED Requirements

### Requirement: 只读采集来源

工具 MUST 以只读方式打开每个来源的存储，且不得修改、迁移或删除来源数据。

#### Scenario: 打开正在写入的来源库
- **WHEN** 来源客户端正在运行且其 SQLite 库存在 WAL 文件
- **THEN** 工具仍能读取已提交和未 checkpoint 的内容，且来源库的修改时间与行数保持不变

#### Scenario: 来源路径不存在
- **WHEN** 某个客户端未安装或其数据目录缺失
- **THEN** 该来源标记为不可用，其余来源继续同步，界面显示不可用原因

### Requirement: 增量同步与去重

工具 MUST 按来源维护同步水位，重复执行同步不会产生重复会话或重复条目。

#### Scenario: 第二次同步没有新内容
- **WHEN** 来源自上次同步后没有变化
- **THEN** 本次同步写入零条新记录，耗时明显短于首次全量同步

#### Scenario: 同一会话追加了新消息
- **WHEN** 某个已有会话新增了轮次
- **THEN** 只补充新轮次和新条目，历史条目的序号与内容保持不变

### Requirement: 以投影库为 Codex 正文来源

对 Codex 来源，工具 MUST 以 `thread_history_1.sqlite` 的条目为准，不得依赖可能已缺失的 rollout 文件。

#### Scenario: 会话的 rollout 文件已不存在
- **WHEN** 某会话在 `state_5.sqlite` 中存在，但对应 rollout 文件已被清理
- **THEN** 该会话的标题、来源和正文仍能从投影库读出并进入索引

### Requirement: 跨客户端项目归一

工具 MUST 以真实工作目录路径作为项目标识，把不同客户端里同一目录的会话归入同一项目。

#### Scenario: 两个客户端在同一目录工作
- **WHEN** Codex 与 Claude Code 都在同一个工作目录产生过会话
- **THEN** 项目视图把它们显示为同一个项目，并分别标注来源

### Requirement: 中文可检索

工具 MUST 支持两字及以上的中文片段检索，包括词中间片段。

#### Scenario: 检索词出现在长句中间
- **WHEN** 用户搜索「止损线」，而正文里是「我的止损线是三千元」
- **THEN** 该条目被命中，并返回包含关键词的上下文片段

#### Scenario: 两字检索
- **WHEN** 用户搜索「止损」
- **THEN** 命中包含「止损线」的条目

### Requirement: 敏感信息遮蔽

工具 MUST 在写入统一库前遮蔽形似凭据的字符串，并记录遮蔽数量。

#### Scenario: 正文包含密钥样式的字符串
- **WHEN** 会话正文出现形似 API Key、访问令牌或私钥的字符串
- **THEN** 写入统一库的内容保留首尾少量字符、中间以掩码替代，界面上可看到遮蔽条数

#### Scenario: 凭据文件本身
- **WHEN** 来源目录中存在认证文件或连接器令牌文件
- **THEN** 工具不复制这些文件的内容
