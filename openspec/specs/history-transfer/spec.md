# 历史交付

## Purpose
把选定来源的历史交给另一个客户端。工具先在写入前给出可核对的预览，列出会话数、消息数、目标位置、重复项与遮蔽条数，再按原生导入、MCP 直读或交接包三种方式执行交付，最后校验目标端是否真的能读到内容。

## Requirements

### Requirement: 同步前必须预览

工具 MUST 在写入任何目标之前生成预览，列出将写入的会话数、消息数、目标位置、冲突项和遮蔽条数。

#### Scenario: 用户选择来源与目标
- **WHEN** 用户在界面中选择一个来源客户端和一个目标客户端
- **THEN** 界面显示预览，且此时目标客户端的数据没有任何变化

#### Scenario: 预览中发现重复
- **WHEN** 待交付的会话在目标中已存在
- **THEN** 预览把它标为跳过，并显示判定依据

### Requirement: 执行与可观察进度

工具 MUST 在执行阶段按阶段报告进度，并在每个阶段给出已处理量和总量。

#### Scenario: 执行中的进度
- **WHEN** 同步正在运行
- **THEN** 界面依次显示读取、归一化、遮蔽、写入、校验五个阶段，当前阶段显示百分比

#### Scenario: 用户中途取消
- **WHEN** 用户在写入阶段取消同步
- **THEN** 已写入的目标记录被回滚或标记为未完成，统一库保持一致，界面报告取消位置

### Requirement: 按目标能力选择交付方式

工具 MUST 在预览中写明本次交付采用原生写入、MCP 直读还是交接包，并且只对支持的目标执行原生写入。

#### Scenario: 目标支持原生导入
- **WHEN** 目标客户端提供官方导入入口
- **THEN** 工具写入标准交换文件并调用该入口，执行后校验会话确实出现在目标中

#### Scenario: 目标不支持原生导入
- **WHEN** 目标客户端没有可用的导入入口
- **THEN** 工具优先生成 MCP 直读配置，让目标客户端能检索来源历史；不支持 MCP 时才生成交接包

#### Scenario: 只有一个客户端可用
- **WHEN** 本机只安装了 Codex 和 WorkBuddy
- **THEN** 界面只显示这两个来源和目标，其余来源不出现，同步流程不因缺失的客户端中断

### Requirement: 写入前备份与失败回滚

工具 MUST 在写入目标客户端前记录改动前的状态，失败时能够恢复到同步前。

#### Scenario: 写入过程中目标客户端报错
- **WHEN** 目标写入返回错误或校验不通过
- **THEN** 工具恢复到同步前状态，保留错误原因，统一库中的来源记录不受影响

### Requirement: 同步结果可核对

工具 MUST 在执行结束后报告成功、跳过、失败的会话数，并给出目标中的验证结果。

#### Scenario: 同步成功
- **WHEN** 全部写入和校验完成
- **THEN** 结果显示成功数量、跳过数量、耗时，以及目标客户端中可查到的会话标识

### Requirement: 交接包写入后可被取回

系统 SHALL 让每份交接包在写入后立刻可检索、可按标识取回、可按来源会话列出。写入成功 MUST 返回交接包标识，取回时给出标题、正文、待办、目标客户端、来源会话与写入时间。

#### Scenario: 写完之后马上检索

- **WHEN** agent 写入一份包含「表格工作台宽表上限」的交接包，紧接着检索这几个字
- **THEN** 检索结果里出现这份交接包

#### Scenario: 按标识取回

- **WHEN** 另一个客户端拿着交接包标识请求内容
- **THEN** 返回完整正文与待办，并给出写入时间与目标客户端

#### Scenario: 标识不存在

- **WHEN** 请求的交接包标识在库里不存在
- **THEN** 返回错误并说明找不到，MUST NOT 返回空文档冒充成功

### Requirement: 交接包与传输记录分开标识

系统 SHALL 明确区分 agent 写入的交接包与同步过程中产生的传输记录，两者使用不同的状态取值，读取交接包时 MUST NOT 把传输记录当成交接包返回。

#### Scenario: 库里同时有两者

- **WHEN** 库里既有 agent 写的交接包，也有同步留下的传输记录
- **THEN** 列出交接包时只返回前者，并在结果里说明另有若干条传输记录未计入

#### Scenario: 旧记录没有状态

- **WHEN** 库中存在早前写入、没有状态标记的交接包记录
- **THEN** 按交接包读取时把它们一并视为交接包，不因缺字段而丢失
